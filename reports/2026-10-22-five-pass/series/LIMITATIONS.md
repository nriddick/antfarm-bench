# Library-limitation statements in producer reports (keyword extract; read in context)

- **antfarm / opus-high / pass1 / opt1:** - **Frames:** the adapter already scales nearly linearly, so the remaining loss should be the last partial round of each dependent wave. For example, frame-gol-small's GoL batch has 16 grains on 15 workers. Changing publication order can't help, because the Farm consumes roughly in arrival order.
- **antfarm / opus-high / pass1 / adapt:** - **Oversubscription:** Antfarm can't put two workers on one CPU (one pool per process, duplicate CPUs collapse). Every slot without a library worker is a registered reserve thread, pinned to its slot CPU and blocked until `stop`; it never computes. All slots register by explicit index. N stays the exact registered count: 15 threads compute for native at N≥15, and up to 30 for frames.
- **antfarm / opus-high / pass1 / adapt:** - The 1–4% composite loss at N=8/15 needs a paired comparison to separate it from drift. Per-group Farms can't balance work across groups; the library would need its per-group host primitive (on the roadmap) to do that.
- **antfarm / opus-high / pass1 / adapt:** - Antfarm can't oversubscribe, so registered slots beyond its workers are idle by design.
- **rayon / opus-high / pass1 / opt1:** - **Frames:** Rayon's automatic splitting merges about 16 grain-sized chunks into one piece that can't be stolen once it starts.
